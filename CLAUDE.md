## Repository layout

This workspace contains three sibling directories:

- `overlay-prototype/` — **Active workbench.** Vanilla-JS + Vite prototype that renders Chick-fil-A menu boards by overlaying dynamic price/calorie text on a background image. This is the shape the new prototype is taking per `OVERVIEW.md`.
- `ai-menuboard/` — Python FastAPI backend implementing an agentic pipeline that generates full Angular 18 codebases from a prompt + reference image. Inherited from another developer; **reference material**, not the active build path.
- `ai-menu-board-output/` — Storage-only git repo where `gitlab_publisher.py` pushes per-job artifacts from the Python pipeline.

`OVERVIEW.md` at the root describes the prototype goal. The current direction is the simpler runtime-overlay approach in `overlay-prototype/`, not the full Angular generator in `ai-menuboard/`.

## overlay-prototype (active)

Vite dev server + static JSON data + Node build step. No framework. **Build-time composition**: a Node script merges design slots + pricing into per-(store, screen) static HTML overlay fragments; the browser just stacks a bg image under a fetched overlay HTML. Naming mirrors the Angular shape the Python pipeline emits (`ManifestFetchService`, `DynamicViewComponent`, `src/assets/active.json`) so the eventual port is mostly file moves.

### Run it

```bash
cd overlay-prototype
npm install
npm run build:overlays         # regenerate overlay artifacts whenever data/ changes
npm run dev                    # Vite dev server on :5173
```

`build:overlays` must run at least once before `dev` (the frontend fetches `/assets/active.json`, which is a build output).

### Data lifecycle (important)

Two independent update cadences, never share a file:

- **Designs** — rare, generated by analyzing menu-board PNGs via `scripts/figma-gemini-debug.js`. Each design is a self-contained artifact: background image path + flat list of text slots with positions.
- **Pricing** — frequent, per-store. Comes from POS/pricing system. Independent of designs; overwriting a pricing file does not require re-extracting any design.

`scripts/build.js` composes both inputs into two independent output streams per (store, screen):
- **Background image** — shared across all stores using that design. Changes only when the Figma sync runs. CDN-cacheable essentially forever.
- **Overlay HTML** — ~1–5KB fragment with absolutely-positioned `<div>` elements. Regenerates when that store's pricing or design changes.

Splitting them lets a pricing update invalidate only the tiny overlay file, not the heavy bg image. This is the whole point of build-time composition.

The frontend is dumb — it fetches `active.json`, stacks the two layers, done. It has no awareness of slots, variants, fields, or the pricing schema. Those concerns live exclusively in `scripts/build.js`.

### Schema

**Design** (`data/designs/design-*.json`) — authoring input:
```json
{
  "id": "design-a",
  "backgroundImage": "/assets/test-bg.png",
  "slots": [
    { "itemId": "cfa-chicken", "variantId": "meal", "field": "price",    "x": 268, "y": 540 },
    { "itemId": "cfa-chicken", "variantId": "meal", "field": "calories", "x": 336, "y": 540 }
  ]
}
```

Each slot is independent — `{itemId, variantId, field, x, y}`. `field` is `price` | `calories` (extensible: `promo_tag`, `allergen_note`, etc.). Coordinates are pixels in a 1920×1080 menu frame, anchored at the top-left of the rendered text. The renderer applies fixed font sizing/styling per `field` — text does not scale with the bounding box; only the start position comes from the slot. A slot renders exactly one text block.

**Pricing** (`data/pricing/store-*.json`) — authoring input:
```json
{
  "storeId": "store-001",
  "items": {
    "cfa-chicken": {
      "variants": {
        "meal":   { "price": 10.45, "calories": 1050 },
        "entree": { "price": 6.49,  "calories": 440 }
      }
    }
  }
}
```

Variant vocabulary is free-form strings (`meal`, `entree`, `meal-8ct`, `entree-12ct`, `base`, `with-toppings`, …) — no enum to maintain. The build script resolves `pricing.items[itemId].variants[variantId][field]`; missing values emit `—` with a `.missing` class per-slot, not per-item. A design referencing a variant the store doesn't carry shows `—` for that one slot only.

**Registry** (`data/registry.json`) — authoring input:
```json
{
  "stores": {
    "store-001": {
      "name": "Atlanta - Peachtree",
      "screens": { "01": "design-a", "02": "design-b", "03": "design-c" }
    }
  }
}
```

The inline `screens` map is a prototype shortcut. Production will introduce a middle `layouts` tier (~5–10 named layouts shared across ~500 stores, each with screen count + design assignments). Extracting this is a one-file change: stores reference `layoutId`, a new `layouts.json` holds the mappings. The build script and frontend paths don't change.

**Manifest** (`public/assets/active.json`) — build output, runtime-fetched:
```json
{
  "generatedAt": "2026-04-16T...",
  "stores": {
    "store-001": {
      "name": "Atlanta - Peachtree",
      "screens": {
        "01": {
          "designId": "design-a",
          "background": "/assets/test-bg.png",
          "overlay": "/overlays/store-001-01.html"
        }
      }
    }
  }
}
```

Mirrors the role of `src/assets/active.json` in the Python prototype's generated Angular app (fetched at startup by `ManifestFetchService`), but carries artifact pointers instead of menu content — because our prototype does build-time composition and theirs does not.

### Slot extraction (current pipeline)

`scripts/figma-gemini-debug.js` is the active extractor. It bypasses the Figma MCP entirely and feeds Gemini a local PNG. This was a deliberate simplification — the earlier MCP-based scripts (`figma-claude.js`, `figma-gemini.js`, `figma-gemini-2.js`, `figma-gemini-3.js`) had silent tool-call failures that caused Gemini to hallucinate items and coordinates. Sending the rasterized PNG inline removes the MCP failure surface so detection accuracy can be evaluated cleanly.

How it works:
1. Reads `data/test-data/{DESIGN_ID}.png` (currently 1920×1080 exports of each design).
2. Sends the image as inline base64 to Gemini with the items catalog and a JSON-schema-constrained prompt (`box_2d` normalized 0–1000, plus `itemId`, `variantId`, `field`, `confidence`, `reasoning`).
3. Converts the returned boxes to pixel space, taking the top-left `(xmin, ymin)` of each box as the slot's `(x, y)` anchor (the renderer uses fixed font sizing — only the start position is consumed).
4. Writes three artifacts to `debug/`:
   - `{designId}.raw.json` — Gemini's raw structured response
   - `{designId}.slots.json` — pixel-space slots with both anchor and full bounding box for inspection
   - `{designId}.boxes.html` — the source PNG with every detected box drawn over it, color-coded by field, with reasoning tooltips and a summary table. Items not in `items.json` are flagged in red dashed.
5. Also overwrites `data/designs/{designId}.json` with the slot list so `npm run build:overlays` can pick it up.

The `DESIGN_ID` constant at the top of the script is currently edited by hand to switch between designs. Run via `npm run figma:debug`. Required env: `GEMINI_API_KEY` (and optional `GEMINI_MODEL`, defaults to `gemini-3.1-pro-preview`).

The catalog-membership guardrail (`inCatalog` flag in the debug HTML) makes hallucinated items obvious at a glance, which is the primary thing that broke earlier iterations.

### What's next to wire

- **Loop debug script over all designs** — currently `DESIGN_ID` is hand-edited; lift it to a CLI arg or iterate over `data/test-data/*.png`.
- **Figma export automation** — `data/test-data/*.png` is currently exported manually from Figma. Either re-introduce an MCP fetch step (now that the rest of the pipeline is debuggable) or use the Figma REST API to render nodes to PNG.
- **Right-anchor / center-anchor support** — the renderer treats slot `(x, y)` as a top-left CSS anchor. Right-aligned price text in the design will visually drift unless either the box's `xmax` is used or the renderer learns a per-slot/per-field anchor mode.
- **Layouts tier** — add when the schema's inline screen-map shows strain, not before.
- **Angular port** — direct mapping: `src/services/manifest-fetch.js` → `src/app/core/services/manifest-fetch.service.ts`, `src/views/dynamic-view.js` → `src/app/features/menu/dynamic-view/dynamic-view.component.ts`, `public/assets/active.json` → `src/assets/active.json`. The build step (`scripts/build.js`) survives unchanged; it produces artifacts Angular consumes the same way vanilla JS does.
